# GTNH → 1.21.1 移植进度（2026-11-17）

## 一句话结论

映射层已经做到「每个引用都有据可查或明确标记为需补」：**508,927 次配方引用全部有归属**，
其中 **43.6% 用 GTCEu / TiC3 包内真实注册证据逐条核对过**；剩余缺口按「爆改 GTCEu 补注册」
拆成三档，**61.3% 的 GT 缺口只需加材料定义**，不用写物品逻辑。

## 本轮做完的事

### 1. 发现并利用 GTCEu 的中文语言文件（最大收益点）
GTCEu 包里自带 `zh_cn.json`（5,571 键 / 786 个物品中文名 / 653 材料中文名 / 103 形态模板）。
用 1.7.10 侧导出的 `dn`（中文显示名）反向查真实 id：
- 精确物品名命中 → `gtceu:<id>`
- 「材料中文名 + 形态中文模板」（如 `%s锭`→`ingot`）组合命中 → `gtceu:<material>_<prefix>`

净收益 **517 条 / 4,960 次引用**，全部标 `verified=zh_lang`。
其中曾踩过一个坑：模板正则最初写成 `re.escape(...).replace("\\%s","(.+)")`，`%` 不被转义导致
替换失效、材料组合命中 0 条；改成 `replace("%s","(.+)")` 后正常。

### 2. 矿辞 → 1.21 标签 / 工具映射
- 确认 GTCEu 包内 **179 个 tag 文件**（`data/**/tags/**`，`values` 数组），自有标签 41 个，
  通用标签在 `data/c/tags/item/*`。**没有** `c:tools/hammer`、`c:ingots/*` 这类材料通用标签。
  → 所以「矿辞换标签」不能凭空编 id，只映射到 GTCEu 实有标签（12 个可确证的）。
- 解出 GTCEu 工具注册方式：`item.gtceu.tool.<type>` 是 `%s` 模板（`hammer→%s锻造锤`、
  `file→%s锉`、`saw→%s锯`、`wrench→%s扳手`、`screwdriver→%s螺丝刀`、`mallet→%s软锤`、
  `mortar→%s研钵`、`wire_cutter→%s剪线钳`…共 40 个 `gtceu.tool.class.*`），
  对应 1.7.10 的 `craftingTool*` / `toolHead*`。
- 净收益 **308 条 / 1,923 次**（tag 1,357 + 工具 566）。

### 3. 定死 TiC 的落点（重要结构发现）
下载并拆了 1.21.1 唯一的 TiC 系实现（`TinkersConstruct-Unofficial-Port-1.21.1-1.6.1`，27.9 MB）：
- 官方 TiC 在 Modrinth 最高 **1.20.1**，**没有 1.21.1**；
- 这个移植内嵌 **Modern Foundry**，命名空间是 **`modernfoundry`**；
- jar 内 `assets/tconstruct` 条目数 **= 0**，即 **1.21.1 根本不存在 `tconstruct` 命名空间**。

于是把 `tconstruct:` 的 58,439 次引用按真实注册名重新落点：
- 同名直接命中：3,452 条 / 24,847 次
- TiC2→3 改名命中：731 条 / 14,033 次
  （`tool_rod→tool_handle`、`tough_rod→tough_handle`、`binding→tool_binding`、
   `tough_bind→tough_binding`、`axe_head→small_axe_head`、`metal_pattern→pattern`、`cast→blank_cast`）
- **合计 4,184 条 / 38,890 次 = 66.5% 有落点**
- 剩下 6,057 条 / 19,549 次无对应：`chunk`(8,568)、`tgregworks.shardcast`(4,287)、
  `chisel_head`/`shovel_head`/`crossbar`/`full_guard`/`sign_head`/`excavator_head`（各 ~476）

### 4. 「爆改 GTCEu」路线落地成施工清单
按你的思路把 GT 家族的缺口（`gtverse:` 176,211 次引用，88.9% 来自 gregtech/miscutils/bartworks/dreamcraft）
拆成三档：

| 档 | 做法 | 数量 | 引用 | 占比 |
|---|---|---|---|---|
| 1 | 补 Material 定义（GTCEu 形态模板已有） | 2,003 种材料 | 108,023 | 61.3% |
| 2 | 补 TagPrefix（casting/extruder 模具等） | 19 种形状 | 4,681 | 2.7% |
| 3 | 逐项自研（机器、蓝图、特殊装备） | 13,090 项 | 63,507 | 36.0% |

关键量化：**缺的形态只有 35 种，缺的材料有 2,003 种**。GTCEu 是 `Material × TagPrefix` 矩阵注册，
所以档 1 是「加数据定义」不是「写物品代码」，性价比最高的一档。
缺的形态头部：`dust` 26,464 / `bolt` 15,948 / `ingot` 12,798 / `plate` 7,970 / `block` 4,835 /
`rod` 4,465 / `small_dust` 3,704 / `nugget` 3,500 / `gem` 3,165。
需补材料头部：`space` 6,328 / `draconium` 716 / `uranium` 672 / `quantium` 661 / `infinity` 621 /
`bedrockium` 607 / `black_plutonium` 579 / `electrum_flux` 576 / `draconium_awakened` 548 /
`cosmic_neutronium` 524。

已有产出 `materials_to_add.csv`：每个材料带 **GT5u 原名 → 1.21 材料 id → 引用数 → 涉及形态**，
这是分叉注册的直接输入（1,659 种可从矿辞反推原文；487 种需人工补名，其中 `blueprint` 2,727 次最大）。
